# Барбершоп: исходящие звонки — проверяемый прототип

Это ядро телефонного бота по согласованному ТЗ от 19.10.2026. Оно отбирает клиентов для пяти сценариев, исключает дубли, сохраняет итоги звонков, формирует отчёт, принимает команды администратора и проверяет сценарии без реальных персональных данных. В репозитории **нет действующего подключения к телефонной сети, Yandex AI Studio, YCLIENTS или Telegram/MAX**. Прототип нельзя выдавать за готовую систему обзвона.

## Быстрый запуск

Требуется Python 3.11+; внешних пакетов нет.

```powershell
python -m unittest discover -s tests -v
python demo.py
```

`demo.py` использует только вымышленных клиентов и имитацию телефонии. Он показывает очередь звонков, `test_call`, уведомления и отчёт. Данные создаются в памяти и не содержат настоящих телефонов.

## Что реализовано

- Подтверждение за час до визита, обратная связь через 7 дней, напоминание через 40 дней, возврат через 90 дней и отдельный список потерянных клиентов.
- Проверка текущей записи и последнего визита перед постановкой в очередь; приоритет сценариев и запрет повторного рабочего звонка по одному событию.
- Отказ от обзвона, допустимые часы и предел попыток. Точные часы и число попыток — конфигурация салона, значения для демонстрации не предлагаются клиенту как согласованные.
- Команды `/call <сценарий> <ID или телефон>` и `/test_call <сценарий> <имя> <телефон>` с проверкой администратора и ID сообщения. Новое тестовое сообщение можно повторить даже для того же номера, повторная доставка того же сообщения не создаёт звонок.
- Тесты не меняют CRM и не входят в рабочую статистику. Результаты вызовов хранят отдельно согласие на дополнительную услугу и подтверждённое добавление её в запись.
- Уведомления администратору и отчёт по периоду на основе записанных результатов.

## Что требуется для реального запуска

1. Доступ к YCLIENTS и актуальная выгрузка клиентов, описание тарифов/услуг, регламент отмены и переноса.
2. Аккаунт Yandex Cloud с доступом к Realtime API, действующая телефония и согласованное с Yandex Cloud подключение SIP. У Яндекса оно находится в Preview и проводится через поддержку, поэтому один только код не создаст реальные звонки.
3. Выбранный канал администратора: Telegram или MAX, токен бота и список разрешённых администраторов.
4. Согласованные часы звонков, попытки, интервалы повторов, основание обзвона, скрипты, промокоды и тексты о работе с персональными данными.
5. Отдельный пилот на утверждённой группе с реальными тестовыми звонками и сверкой итогов с CRM.

Архитектура сделана так, чтобы интеграции подставлялись в `BotService` через интерфейсы `Crm`, `Dialer` и `Notifier`. Демо-адаптеры в `demo.py` не отправляют звонков и сообщений.
